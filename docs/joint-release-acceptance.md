# 06C-1 — 联合发布、留存与真实登录验收准备

2026-10-03。本文是待执行清单，不是生产验收证明；修改与测试历史仍只记在 [开发修改记录](development-change-log.md)。当前成果位于 `bb2f6e3` 之上的 dirty 工作树，不能把该 HEAD 当成包含全部功能的发布版本。

## 先处理凭证展示风险

本批 RED 测试的缺字段异常曾展开 Settings 对象，包含配置敏感值。没有把凭证抄入本页；忽略目录中的本次 RED JUnit 已定点清除异常文本及消息，保留 case／失败计数。工具输出历史无法撤回，**可能出现的 API key、OAuth secret、会话签名密钥应由持有人按泄露处理并轮换**；不要把新值发到聊天、截图、Git 或验收记录。

本地已对密钥／client ID 字段设置 repr=False，Settings 校验字符串隐藏输入值；这不是对显式 model_dump／errors()／环境文件／进程日志的通用脱敏。新的 canary 测试不使用真实凭证。未撤销／更换真实凭证，未修改运行 `.env`，未重启 NAS。会话签名密钥改变会使旧签名在新 API 下校验失败，需要重新登录；应安排告知与联合配置更新，不承诺无感轮换。

## 两道保存门控与回退

`ANSWER_FEEDBACK_ENABLED` 默认 false；API 和 UI 都从现有 Settings 读取。示例配置也明确 false，**表存在或迁移到 v1.7 不再等于启用**。该配置在进程启动时加载，修改实际环境后需重启／重建相应 API/UI；不是无需重启的远端热开关。

`ChatRequest.allow_feedback_capture` 只接受 JSON boolean，默认 false。UI 在输入框前显示查询日志与保存告知，运营启用后提供默认不勾选的会话级选择；每个聊天／示例／追问请求显式携带 true 或 false。勾选是技术许可信号，不是账号、真人或法律同意证明；当前没有独立同意审计账本，不把此字段加入模型 prompt 或既有请求上下文白名单。

| 服务端开关 | 当前请求许可 | 新完成回答 | 评价端点／UI |
|---|---|---|---|
| false | 未提供／false／true | 不捕获完整回答、不发 receipt，回答流与原 query_log 继续 | POST /feedback 固定 503/no-store；UI 本地关闭时不显示投票控件 |
| true | 未提供／false | 同上 | 既有有效 receipt 仍可评价；取消保存只影响后续回答，不撤销既有数据／权限 |
| true | true | 还须原查询、schema、正常非空有界回答及 commit 都成功 | done 可带 receipt，原文／UI hash 仍重验；失败不打断原回答 |

关闭期间不写新回答或修改当前评价，**不 DROP 表、不删既有 DB／WAL／备份／导出**。流开始和完成时分别检查门控；开始没允许就不回溯收集，结束已关闭不保存／发凭证。取消勾选只停后续保存；清对话／登出清 UI 许可和 receipt，不删除服务器记录；重新启用不会恢复 UI 旧选择。七天仍只约束投票 capability，不是留存期限。

旧 UI→新 API：没有许可字段时默认不新增完整回答，聊天可继续。新 UI→不支持许可字段的旧 API：旧 extra=forbid 契约会拒绝请求，**不去掉字段自动重试以绕过保存许可**。因此发布和代码回退必须验证 API/UI 成套匹配，不能只重启一边；停用新功能优先走配置关闭，不用覆盖生产库恢复旧功能。

## 真实登录／刷新检查（待本人执行）

需真实账号与目标域名确认后，在正常浏览器中执行；记录现象与 pass/fail，不抄邮箱、Google sub、授权 code／state、cookie、session token 或 callback 查询串。

1. 匿名打开确认可浏览，保存许可未勾选；无有效 receipt 的旧聊天没有投票目标。
2. 通过页面发起 Google 登录，确认合法域账号能返回预期 UI，回调参数被消费；拒绝授权／state 不符不应变成登录成功。不要从浏览器地址栏把 code 发到聊天。
3. 登录后的普通页面 rerun 与**完整页面刷新**分别核对是否恢复同一账号状态；检查 `/auth/me` 的成功状态，不保存其身份 body。UI 新标签页按页面加载 cookie 恢复，而不是靠旧 session_state。
4. 过期／坏会话走 401 后应清本标签的恢复 cookie 并要求重新登录；网络故障／503 不等于凭证无效，不据此伪造身份。这里是应用签名会话的恢复／过期，不证明 Google refresh_token 续期。
5. 登出后当前标签及其刷新不应被旧可见 cookie 立即重新登录；已渲染状态、receipt 和保存许可清掉。现有签名 token 没有服务端单会话撤销账本，**不承诺其他已登录标签／被复制的有效 token 同时失效**；需单独记录跨标签现象及产品限制。
6. Search／Programs／独立 Co-op 页的登录入口与返回分别核对。OAuth 回调当前清 query_params，完整分享目的地穿越 OAuth 后恢复尚未实现；精确分享可在登录后重新打开，不把此缺口误写为通过。
7. 联合发布后分别验证保存未勾选与勾选。需要产生聊天／评价行时先获准并设置 eval 标记（普通 UI 不自动添加），明确该动作会写日志／调用模型；不要把开发 smoke 混进真实使用评测。
