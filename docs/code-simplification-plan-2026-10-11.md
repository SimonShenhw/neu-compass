## 2. 先明确不能丢失的功能

| 范围 | 重构必须保留的行为 |
|---|---|
| 搜索 | 别名、混合检索、筛选、候选顺序、top-k、空结果、拒答、可选救援和降级 |
| 聊天 | 多轮历史、追问指代、项目歧义／冲突、检索通知、流式事件、部分回答、错误和最终 done |
| 证据与规则 | 来源关联、AND／OR、年度／路径、partial／unparsed、冲突、未知值和限定说明 |
| 前端与分享 | 页面导航、课程详情、固定输入框、深链接、精确方案引用、刷新和已有状态 |
| 身份与贡献 | OAuth、cookie 恢复、session、登出、Co-op 权限与审核门槛 |
| 私有反馈／导出 | 默认关闭与显式许可、receipt 绑定、失败不发凭证、只读快照、输出白名单和不覆盖 |
| 推理后端 | 支持的后端选择与兜底、输出维度／dtype、数值语义、锁、惰性导入与预热 |
| 离线工具 | 既有 CLI 参数、退出码、输出格式、选择规则、旧数据兼容及可复现评测 |

测试通过是必要证据，不是「所有功能绝对等价」的证明。每批还需核对实际输入／输出、状态变化、副作用、异常与性能边界。

### SIM-01：先抽取明确重复的小型纯函数

**入口**：[embedder.py](../rag/embedder.py)、[onnx_backend.py](../rag/onnx_backend.py)、[openvino_backend.py](../rag/openvino_backend.py)、[课程规则模型](../schemas/course_requisite_document.py)、[方案模型](../schemas/program_plan.py)、[反馈候选模型](../schemas/feedback_candidate.py)、[查询导出模型](../schemas/query_log_export.py)。

**实施范围**：先统一 L2 归一化，再逐项核对课程代码和时间规范化。共享模块保持小而有明确领域名称；不建立杂物式 `utils.py`，不把后端加载或 schema 业务约束一起搬走。

**不变项**：零向量保持零、返回 float32、shape 与既有输入处理；课程代码的大小写／空白／后缀规则；时间格式严格度；Pydantic 字段、extra／strict 策略、序列化和必要的错误契约。需要时保留旧模块的导入别名，避免无关调用方一起修改。

**验收**：

- 归一化覆盖零向量、普通／批量向量、既有空输入和 dtype 行为；同输入的新旧结果一致。
- 规范化覆盖合法边界、非法格式和 schema 嵌套调用；JSON 往返与既有结果一致。
- 公共辅助模块不会在导入时额外加载 torch、ONNX Runtime、OpenVINO 或下载模型。
- 定向测试和全量离线回归通过；保留全部已支持后端，不调整模型参数。

### SIM-02：共用检索决策，保留路由专属语义

**入口**：[search.py](../api/routes/search.py)、[chat.py](../api/routes/chat.py)、[common.py](../api/routes/common.py)、[reranker.py](../rag/reranker.py)、[rejection.py](../rag/rejection.py)。

**实施范围**：共享取候选文本、构建校准门、重排／融合、救援资格判断和决策结果。用明确的结果对象携带 hits、拒答原因和是否救援；HTTP／NDJSON 组装与路由日志仍由对应入口负责。配置／常量不继续通过「聊天路由导入搜索路由」取得。

不要将两条路由强行合成一个入口：聊天的历史、追问、项目规则和流式输出与搜索不同。不要为这项重构改变门控阈值、候选池、融合参数或精确入口的绕过规则。

**验收**：

- 对别名、普通 hybrid、无 reranker、拒答、救援成功／失败／跳过分别固定新旧结果。
- 包含筛选排除、相似课程锚点、k 大于默认池、空候选及原始 query 与扩展 query 的区分。
- 候选顺序、分数、拒答原因、有效筛选、响应与遥测的 `matched_via` 区分不变。
- 每个请求仍独立持有检索诊断；不能将有请求级状态的对象改成全局单例以「省代码」。
- 路由级契约测试仍保留；不只测试抽出来的函数。

### SIM-03：把前端主入口收敛为页面编排

**入口**：[streamlit_app.py](../app/streamlit_app.py)、[state_manager.py](../app/state_manager.py)、[deep_links.py](../app/deep_links.py)、[course_detail_view.py](../app/course_detail_view.py)、[program_view.py](../app/program_view.py)。

**实施范围**：优先复用已有页面模块，把主入口中的导航、聊天区域、单轮提交／展示和详情加载分成清晰职责。单次只迁移一个区块；先保留现有 state key 和调用顺序，不同时重命名全部状态或替换 UI 框架。

**验收**：

- 冷启动、历史重渲染、清对话、课程选择、筛选清除与追问保持一致。
- OAuth callback、cookie 恢复、深链接与 pending navigation 的先后关系不变。
- 隐私告知和项目选择仍在输入之前；固定输入框保持正确布局。
- Streamlit widget 绑定 key 的修改时机合法；不因 rerun 增加模型／POST 调用。
- 反馈许可、receipt 清理及部分回答显示仍走实际页面路径测试。
- 本地页面测试不冒充真实浏览器／账号验收；有浏览器验证时另记环境与结果。

### SIM-04：独立整理文本渲染职责

**入口**：[answer_evidence_view.py](../app/answer_evidence_view.py)、[ui_theme.py](../app/ui_theme.py)、[program_plan_view.py](../app/program_plan_view.py)、[coop_view.py](../app/coop_view.py)、[discover_view.py](../app/discover_view.py)。

**实施范围**：把纯文本渲染工具与证据面板展示分开，减少其他模块为转义而依赖整个证据视图；必要时拆分主题中的 CSS 与展示函数。已有来源标签的公共代码和值域可统一，但 UI 中文标签与 prompt 中的英文解释不要求使用同一文案。

必须继续区分四种上下文：HTML 单行、HTML 块内多行、Markdown 纯文字、模型回答过滤。`_one_line` 去换行与 `plain_text_html` 保留 `<br>` 是有意差异，不是可以直接合并的副本。

**验收**：

- 单行／多行数据不逃出 HTML 块；反斜杠、实体、链接、指令、math、跨 token 输入仍符合现有规则。
- 官方目录链接保持可用；其他不可信文本不新增链接、媒体或指令行为。
- 已记录的格式／复制代价保留，不在重构中偷偷改变。
- 精确输出、随机组合、流式中间帧和长输入测试保留。
- 更改渲染器相关行为或依赖时，另跑 [真实渲染器检查](../scripts/answer_render_check.py) 并记录结果；仅移动代码不宣称浏览器已验收。

旧 prompt、实验脚本、兼容导入和回退入口先核对引用及用途；标记 legacy 或整理目录不等于允许删除。任何删除或改变既有调用方式的建议单独列出，获得确认后再做。

## 4. 纯重构与功能修复分开

以下可以后续推进，但会改变行为，不塞进 SIM 批次里：

- 缓存失败 TTL、手动刷新、登录／权限失效。
- OAuth／全局错误文案与安全日志字段调整。
- 评测器新规则、按课程／字段判分、完整链路测试能力。
- 导出分页、保留期、清理、持久化或数据库迁移。
- 课程对比、结构化证据聊天和选课草案。

如果发现当前行为有问题，先记录，再明确选择「原样重构」还是「另批修复」。不要让用户在一份纯重构 diff 中同时核对新业务规则。

## 5. 每批实施与验证流程

1. 核对当前 HEAD 和 dirty 改动；保存明确的功能／公共契约基线。
2. 补足有缺口的行为特征测试，在改动前确认通过；不要先改测试期望来配合实现。
3. 一次只处理一个边界，保持 API、CLI、持久化格式、默认配置与授权范围。
4. 用确定性替身或合成输入比较新旧结果、调用次数、状态变化、异常和副作用。
5. 运行定向测试及全量离线回归；核心检索／渲染路径还要检查明显性能退化。
6. 记录实际删除的重复点、入口职责变化、剩余兼容层和未核验场景；不只报告「少了多少行」。

建议离线全量命令（WSL 内、仓库根目录；先确认依赖与默认 live 排除配置）：

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B -m pytest tests/ -q --tb=short --show-capture=no -p no:cacheprovider
```

这个命令不代替真实模型、浏览器、账号或生产验收。不为跑重构测试导出密钥／配置，不在失败时直接贴可能含敏感值的原文。仓库历史风格问题不纳入这轮全量清洗；优先检查改动文件的正确性问题。
