# 回答依据与来源回填

本页最初写于 2026-10-01（第四批，当时只有本地实现，没有执行真实数据库迁移、目录回填、Gemini 质量评测或生产部署；测试使用临时数据库、历史 HTML fixture 和模型替身）。2026-10-05 按 `docs/development-change-log.md` 第 12 节更新了「API、提示词和界面共用的契约」一节。之后的上线情况见同一文件第 10 节起：2026-10-04 起线上是提示词 4.1，4.2 要等下次部署。后两节「既有数据库的来源回填」「上线前仍需完成」仍是第四批当时的记录。

## 三类信息不能混用

1. **目录快照**：`course_catalog_sources` 单独保存描述、官方部门页 URL、课程代码/名称、目录学分、已解析先修代码、内容摘要 ID 和导入时间。只接受显式的 `https://catalog.northeastern.edu/course-descriptions/<dept>/` 来源，部门必须与课程代码匹配。URL 校验和内容摘要只能帮助追踪，**不是存档真实性、内容正确性或当前适用性的证明**。
2. **抽取证据**：原 `evidence_snippets` 保留字段、支持值、引文、来源 ID 和抽取置信度。工作量、难度、技能等仍是来源支持的评价/估计，不能称作官方事实；置信度不是事实为真的概率。来源 ID 不等于已核验的全文，也不自动生成链接。
3. **缺失或未核验信息**：没有有效快照就明确缺少目录来源；不能把可能混有 syllabus、评论或生成扩展的 `raw_text` 当成官方描述。旧 `catalog_*` 来源 ID 本身也不够。结构化元数据仍可能缺少逐字段的来源对应，不能因为它出现在课程记录里就视为已核实。

当前目录抓取器的 `CatalogEntry` **不记录抓取时间**，因此回填后的 `retrieved_at` 保持 `null`。不拿导入时间、文件修改时间或本次日期冒充抓取时间。部门页快照也不证明某个学期、校区、教师或班次正在开课。

## API、提示词和界面共用的契约

- `/chat` 首个 NDJSON meta 带 `prompt_version`（当前 `"4.3"`：在 4.2 的基础上，存档副本那句每个回答只说一次，数值冲突时两个数都要写出来；4.2 从未部署），每个结果附 `answer_evidence`。`GET /course/{course_id}` 也返回该结构，不改持久化 `Course` schema v1.1。
- `answer_evidence` 包含 `catalog`、`field_evidence`、`source_review_ids`、`missing_fields`、`warnings`。缺失包括官方描述及常用选课字段；`None`/空列表表示记录未提供，数值 0 不当成缺失。这不是完整 syllabus 字段的覆盖率报告。
- v4 提示词与 SSE meta 使用同一份读取结果，避免模型拿到一套依据、界面显示另一套。课程详情涉及培养方案时另外标记未核验 seed；chat 的培养方案捷径也标记该限制。不同查询语境的警告不必逐字相同。
- 目录与课程学分冲突、数值估计与支持值冲突时保留两边并警告，不静默改写课程或选择一个值。先修代码列表不保留 AND/OR；培养方案 seed 不等于正式 Plan of Study 或选课资格保证。
- v4 把查询、历史、来源块作为引用/JSON 数据，并要求忽略其中嵌入的指令；历史只能帮助解析所指，不能补造课程事实。移除按 5xxx/6xxx/7xxx 判断难度或首学期适合度的捷径。合成记录不应成为真实课程推荐。
- 每门课传入最多 1200 字符目录描述、3 条各最多 300 字符引文，标记截断和省略条数；优先覆盖工作量、难度、技能的不同字段，再补重复证据。部分元数据列表也限条数。完整快照和证据可从详情查看；摘录不等于完整来源。
- **4.2 起快照 ID 与来源 ID 不进提示词**（4.1 的回答会原样印出 `catalog:` 加 64 位摘要和 base64 评价 ID）：
  - 提示词里的目录快照去掉 `snapshot_id`。
  - 引文的 `source_id` 换成来源类型 `source_kind`，按 ID 前缀判断（`rag.answer_evidence.source_kind`）。提示词里用英文标签，界面用中文标签：RateMyProfessors 教师评价、Reddit 讨论、课程大纲、抽取时用的课程文本、合成测试数据、其他来源。
    - RMP 评价是按姓名搜索到的老师（取第一个匹配）的评价，按老师抓取、不按课程筛选。所以提示词里的标签写明「按姓名匹配到这门课任课老师的评价，可能是关于别的课」。
    - `catalog_` 来源是抽取时课程的 `raw_text`，可能混有目录以外的文字，不是记录的目录快照。
  - `source_review_ids` 换成 `recorded_sources`，只列来源类型、不给条数。ID 列表是抽取模型自己写的，可能重复；给出条数，模型容易说成「这门课有 N 条评价」。规则也写明它不核实任何字段，不支撑学分、学期、先修这类目录事实。
  - 规则要求：
    - 用普通说法归因；
    - 把目录写成指向 `catalog_url` 的 Markdown 链接，中文回答用「NEU 官方课程目录」，英文回答用「NEU course catalog」，并用一句白话说明内容来自目录的存档副本、不是实时核对；
    - 引文本身没写出来的数值是抽取时的估计，不能说成评价里报告的；
    - 不写任何内部 ID、哈希、字段名或提示码；
    - 「培养方案」页不加链接。
  - 课程记录里的 `course_id`（例如 `neu-cs-5800`）仍在提示词里，4.2 之前就是这样。
  - meta 与课程详情里的 `answer_evidence` 不变，ID 仍可追溯。这只是改提示词输入的投影，不改契约本身。
- 聊天历史保存来源/缺失结构，历史与实时卡片共用展示函数。卡片显示简短缺失列表和关键警告，详情显示完整列表、来源、导入时间及未知抓取日期。快照只显示摘要前 12 位，完整 ID 放在悬停提示里；格式不对的 ID 显示「格式异常」，不回显（说明文字和悬停提示都会渲染 Markdown）。记录来源按类型汇总条数（重复的 ID 只算一次），原始 ID 收在折叠区。旧聊天记录没有此结构时仍可显示；非法快照不显示可点击链接、不导致面板崩溃。来源 ID 与引文按纯文本展示。
- 回答文本是模型输出，按不可信 Markdown 处理（`app.answer_evidence_view.answer_markdown`，一遍线性处理）：
  - 先把指向官方目录院系页的链接（`[标签](URL)`、`<URL>`、裸 URL）换成占位符，最后还原成 `[标签](URL)` / `<URL>`（去掉标题和 URL 两边的尖括号）。判断用与快照 URL 校验同一个正则，但不像快照那样核对院系与课程代码是否一致。
  - 其余文字只插入字符：反斜杠全部翻倍；每个 `http(s)://`、`www.` 的首字母后插一个不可见、不断行的 word joiner（U+2060），代码围栏后紧跟的 `math` 信息串也插一个（Streamlit 会把 ```` ```math ```` 渲染成 KaTeX）；实体、HTML/自动链接、链接目标、引用式定义/脚注、图片、公式、指令/短代码的开头字符前加反斜杠，名字前的 `:` 后面再插一个 word joiner（Streamlit 在解码后的文字里替换 `:smile:` 这类短代码）。
  - 结果：强调、列表、标题、表格、代码照常显示，目录链接可点，其他东西都不会变成链接、图片、HTML、公式、指令或短代码。除了 Streamlit 自己的排版替换（见代价），渲染器显示的就是检查过的文字。
  - 代价：模型写的反斜杠、实体、公式、`:red[...]` 这类指令和 `:smile:` 这类短代码原样显示；其他链接显示成 Markdown 原文，复制出的非目录网址、`:名字` 和代码围栏的 math 信息串带着那个不可见字符；代码里看得到插入的反斜杠，目录网址在代码里带尖括号；表格里的 `\|` 会变成分列；math 代码块显示成普通代码；Streamlit 的排版替换仍然生效（`->`、`<-`、`<->`、`--`、`>=`、`<=`、`~=`），以标点开头的少数 emoji 短代码（`:+1:`）仍会变成 emoji；邮箱地址仍可能显示成邮件链接。
  - 流式输出最多每 0.1 秒渲染一次已到达全文的过滤结果，结尾再渲染一次（中途出错也是）；历史渲染同样过滤；学生自己输入的文本原样显示。
  - 验证：markdown-it-py 当独立判定器（精确输出、按固定种子随机拼接的 Markdown 片段、纯文字原样显示，另查引用式定义、math 代码块、短代码，以及源文本里的 `$`、`:` 都已转义）和线性耗时测试；Streamlit 1.57 真实渲染器用 `scripts/answer_render_check.py`（加 `.js` 控制台脚本）手动检查，最近一次（10-07）851 个用例的结果见 `docs/development-change-log.md` 第 13 节。
- 数据库里的文字也按纯文字显示（课程名曾由模型写入，字段名、先修 ID 也可能来自模型抽取）：
  - 进 HTML 卡片的先转义并去掉换行（一个空行就会结束 HTML 块，后面的内容按 Markdown 解析）：课程详情头部、主题、搜索结果、详情里的培养方案行、培养方案页的方案卡片和课程表、入门推荐、Co-op 列表和首页预览；
  - 放进 Markdown 的用 `literal_markdown()`（转义每个 ASCII 标点、连续空白变成一个空格）：先修行的课程代码和名称、培养方案说明、方案范围里的 concentration、证据面板里未知的字段名和提示码；只有 ID 的先修行放进单行代码片段；
  - 先修图（graphviz）标签里的反斜杠换成 `/`，引号转义。
- 网址里的参数同样不直接进 Markdown：分享链接的课程或项目引用折成一行放进代码片段；登录失败时只显示格式正确的 OAuth 错误码（小写字母和 `_`），其他情况显示固定文字。
- 检索分数条只是候选内部的相对排序分数，不表示事实可信度。

`llm/prompts/chat_v3.py` 保留不变，新增 v4 而不覆盖旧版本。提示词约束及离线测试不保证真实模型始终遵守，也不构成 prompt injection 防护证明；真实回答的来源归因、截断影响与中英表现仍需独立评测。

改了提示词之后，用 `scripts/eval_answers_live.py` 复核真实回答：
- 证据只从线上 `GET /course/{id}` 取，请求带 `X-Eval-Run` 标记，不会被当成学生查询；
- 提示词用本地的 `chat_v4.py`，按 `/chat` 的方式构造；模型调用走 `/chat` 同一个函数和参数，调用次数有上限；
- `eval/answer_checks.py` 检查内部 ID、链接、评价条数、RMP 归属（硬检查），以及各项说明、估计值措辞、链接标签语言、重复的存档副本句（给人看的信号）；
- RMP 归属看引用评价的那几句：连续的评价句算一段，每段自己要提到老师，或用他/她指代，别处无关的 "professor" 和网站名本身都不算；每一段都要有「可能是别的课」的提示，在段内或紧接着的下一句。「评价方式」「成绩评价」这类说的是考核，不算引用评价。估计值措辞和存档副本句也按句子判断；英文句号会分句，4.0、e.g.、Ph.D.、U.S. 里的点不算；
- 评价条数不把课程代码的数字（"CS 5800 students"）和隔着介词的短语当条数（以介词开头的连字符词如 "in-depth" 不算介词）；抓取日期/存档副本的说明只在回答链接了目录时才要求：说日期或「不是实时」的措辞在哪句都算，单独的「存档」「副本」只在不是「没有目录描述」的分句里才算（按 `；` 分句）；「无法实时核对目录」不算「没有目录」，「无法在目录中找到」算；
- 每次运行都记录状态：`complete`（计划的每次调用都有回答且检查过）、`incomplete`（有调用失败、调用上限提前停止，或没有回答可检查）、`dry run`，写在 `summary.md` 的标题行。退出码：0 完整且没有硬失败（或空跑），1 有硬失败，2 准备阶段、参数或输入出错（API 不可达或返回非 200、问题文件或 `--rescore` 文件缺失或格式不对、数据对不上、`--out` 目录建不了或写不进；问题的 `qid` 只能是 1–64 个字母、数字、`_`、`-` 且不分大小写也不重复，因为它是输出文件名），3 不完整。第一次调用模型之前会先构造并保存好全部提示词和上下文；`--rescore` 先检查报告的形状和类型，检查本身出错时保留 traceback，不算成 2；
- `--dry-run` 只生成并保存提示词和上下文（`prompts/<qid>.txt`、`.context.json`）；`--rescore` 用调整后的检查重评已保存的回答，不再调 API 和模型，保留原来那次运行的错误。

这些检查只标出可能的问题，不能证明回答正确，结果仍要有人读。

## 既有数据库的来源回填

新初始化库由 `db/init.sql` 创建 v1.4 来源表。既有库在没有表、没有快照或快照不合格时，读取路径降级为来源缺失，**不会在请求里自动建表、猜来源或清空课程字段**。不统计或宣称运行库的来源覆盖率。

`scripts/sync_catalog_sources.py` 只从已有 `CatalogEntry` JSONL 存档回填。必须显式提供一个存在的 DB 文件和存档目录，默认 SQLite `mode=ro`，不访问网络，不自动采用配置中的运行库。

先通过受支持的备份方式获得一致的数据库副本，再将可信存档放到独立目录。以下仅为副本操作示例，不是已执行的命令；用实际副本路径替换示例路径，不要指向生产库：

```powershell
# 在项目已配置的 Python 环境中执行；先检查统计。
python scripts/sync_catalog_sources.py --db-path "H:/neu-compass-backup/rehearsal.db" --catalog-dir "H:/neu-compass-backup/catalog-archive"

# 人工检查来源与匹配情况后，才显式写入副本。
python scripts/sync_catalog_sources.py --db-path "H:/neu-compass-backup/rehearsal.db" --catalog-dir "H:/neu-compass-backup/catalog-archive" --commit
```

行为边界：

- 全部存档先解析/校验，再开始写入。缺少显式 URL、非法 URL、坏 JSON 或同一代码的冲突存档使整次操作失败，不任意挑最后一条。不够可信的历史存档不能靠手工拼 URL 自动升级为官方证据。
- 必须唯一匹配现有课程代码且名称完全一致；未知代码、多个相同代码、名称不一致分别计入跳过统计，不自动建课程、改名或关联到近似课程。
- `--commit` 在一个事务里建 v1.4 表、记 schema 版本并保存所有匹配快照；写入失败连新增 DDL 一起回滚。相同内容重复回填不覆盖原导入时间。输出提供 `matched`、`skipped_*`、`unchanged`、`would_store`、`stored` 等统计，应检查而不能只看退出码。
- 回填不改 `courses` 的任何列，也不改富化字段、混合 `raw_text`、search expansion、pending/indexed 状态或索引文件；无需因此重建 FAISS/BM25。CLI 失败不创建拼错路径的空数据库。
- 来源表目前每门课只保存一个快照，更新会替换上一份；不是多版本历史仓库。内容摘要不含导入/抓取时间，原始 JSONL 与旧版本需要另外保存。
- 若没有可校验存档，不执行来源回填；读取端继续提示缺失。v1.4 不替代第三批独立的 v1.3 Co-op 迁移，也不自动部署 API/UI。

**课程名修复（2026-10-06）**：线上库里 CS 5200 存的 `primary_name` 是它描述的第一句话（"Introduces relational database management systems…"），多半是 2026-06 之前「把整个 LLM 输出写回」的富化留下的（现在 `llm/review_enrichment.py` 只合并软字段，有测试钉住名称不被改）。因为回填要求名称和目录标题完全一致，这门课一直被计入 `skipped_title_mismatch`，没有目录快照。`scripts/repair_course_names.py` 修这一类：

- 默认只读，列出所有与存档目录标题不一致的课程；
- `--commit` 只修「存的名称以句号等结尾、原样出现在这门课自己的描述或 `raw_text` 里」的记录，其他不一致（改名、版本差异）只列出、不改；
- 修复走 `CourseRepository.rename()`：名称列和 Course JSON 一起改，status 不变。两个索引都不读名称（FAISS 嵌入 `raw_text`，BM25 索引 `raw_text` + `search_expansion`），所以不用重建索引，课程也不会从搜索里消失。

本地开发库（7 月的副本）只报出 CS 5200 一门；另有 AAI 6600 被列为其他不一致（存的是 syllabus seed 的 "Introduction to Artificial Intelligence"，目录标题是 "Applied Artificial Intelligence"），需要人来定，不自动改。

下次部署时在生产库上照这个顺序做（先 `chown` NAS 项目目录、做好部署前备份）：
1. `python scripts/repair_course_names.py --db-path <生产库> --catalog-dir <v1.4 回填用的同一份存档>`，看报告；
2. 确认后加 `--commit`；
3. `python scripts/sync_catalog_sources.py --db-path <生产库> --catalog-dir <同一份存档>`，确认 CS 5200 变成 matched、`would_store` 符合预期，再加 `--commit`；
4. 不需要重建索引，也不需要重启 API：`/course` 和回答每次请求都从库里读名称和快照。

普通 `ingest_neu_catalog.py` 现在同时存来源快照，并在缺表或来源不合格时失败。**不要用它给既有富化课程补来源**：原摄取会重写 Course、把状态置为 pending 并要求重建索引。回填工具就是为避开这些副作用而单独提供的。
